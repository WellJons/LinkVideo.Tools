# LinkVideo.Tools

Основная версия **0.8** + тестовая ветка **0.9-dev (сеть и камеры)** — утилита для Windows, дополняющая локальный LinkVideo.Server.

## Функции
- Поиск записей Nimble по индексу и отображение реальных временных интервалов и пропусков
- Экспорт локальных видеозаписей в MP4 через FFmpeg
- Проверка процессов LinkVideo.Server и Nimble, настраиваемый мониторинг службы Nimble
- Экспериментальный запуск **штатной синхронизации** через локальный API LinkVideo.Server
- Диагностика по журналу каждые 3 секунды: запрос интервалов, получение upload-token, ошибки JSON, попытки передачи .dat и индекса
- Отмена только ожидания локального ответа (до 2 минут), последующее наблюдение за логами в течение 3 минут

## Новое в 0.9-dev: диагностика клиентской сети
- Вкладка **«Сеть и камеры»**: поиск устройств через ONVIF WS-Discovery, Hikvision SADP, Dahua DHIP и XMEye DVRIP (XM/Sofia). Протоколы работают по локальному UDP-мультикасту/широковещанию; поиск по другой VLAN может быть ограничен сетью. Ответ SADP/DHIP/XM может содержать адрес устройства из другой подсети.
- Выбор найденного IP или ввод IP вручную: три проверки ICMP, доступность основных TCP-портов (80, 443, 554, 8554, 8000, 5000, 37777, 34567) и ответ RTSP OPTIONS без пароля. Открытый порт и RTSP 200/401 **не означают**, что воспроизводится видео.
- **Мониторинг ICMP**: запуск и остановка оператором, одна проверка каждые две секунды, статистика успешных/неуспешных ответов, времена начала серий отсутствия ответов.
- Вкладка **«Wi-Fi»**: Windows Native WLAN API, найденные BSSID/SSID, 2,4/5/6 ГГц, канал, RSSI и уровень качества, отчёт TXT.
- Дополнительные результаты диагностики добавляются в общий журнал и экспорт. Пароли для поиска устройств не нужны, состояние камер не изменяется.

**Ограничения:** сканирование Wi-Fi показывает эфир **рядом с компьютером**, а не там, где висит камера. Смена BSSID самой камеры, данные клиента роутера, реальные RTSP-кадры/кодеки, конфигурация устройства и архив в облаке пока не проверяются. ICMP может быть отфильтрован даже на исправной камере. Первую проверку выполнять в своей или разрешённой тестовой сети.

## Важно о выгрузке
Текущий вызов `GET /api/sync-with-dat?start_dt=...&end_dt=...` запускает синхронизацию архива для всех настроенных камер за период. Это **не принудительная перезапись** уже существующей облачной записи. HTTP 200 подтверждает выполнение запроса локального API, **не успешную отправку архива**. Запускать только на своей тестовой системе до полноценной проверки.

Автоматический перезапуск Nimble отключён по умолчанию. Утилита не изменяет локальные .dat и индексы.

## Сборка
Требуется Go 1.23+:
```powershell
go test ./...
go vet ./...
$env:GOOS="windows"; $env:GOARCH="amd64"; $env:CGO_ENABLED="0"
go build -ldflags="-H windowsgui -s -w" -o LinkVideo.Tools.exe .
```
Или `build_windows.cmd`. Для экспорта MP4 необходим FFmpeg. Исходная инструкция: [README_RU.md](README_RU.md).

## Дальнейшее развитие
Подтверждение реальной выгрузки, независимый модуль принудительной загрузки только после проверки протокола, оформление в стиле LinkVideo.Helper, проверка кодеков реального потока (только с согласия оператора и учётными данными), анализ роуминга по логам роутера, тестирование Wi-Fi/поиска на настоящих камерах и детализация облачной диагностики.

В репозиторий **не входят** проприетарные исполняемые файлы LinkVideo.Server, клиентские видеозаписи, конфигурации, RTSP-пароли и ключи.

# LinkVideo.Server Tools v0.7 — тестовая сборка

## Главное: ручной запуск штатной выгрузки архива

Вкладка **«Архив»** → выберите существующий непрерывный участок записи → **«Выгрузить в облако»** → укажите диапазон → введите **локальный пароль управления LinkVideo.Server** (не пароль камеры и не пароль биллинга) → подтвердите запуск.

В версии LinkVideo.Server 1.1.12 подтверждён локальный маршрут `GET /api/sync-with-dat?start_dt=...&end_dt=...`. Приложение выполняет локальный вход `POST /api/auth/login` с JSON `{"password":"..."}`, получает токен в памяти и вызывает синхронизацию через штатный обработчик LinkVideo.Server с заголовком `token`. Время передаётся в Unix-секундах. Все вызовы направлены **только на 127.0.0.1:48518**. Пароль и токен не сохраняются в файл.

**Ограничения:**

- Маршрут не принимает идентификатор камеры: вызов относится ко **всем камерам**, настроенным на данном LinkVideo.Server, за указанный диапазон. В окне есть предупреждение и подтверждение.
- Штатный алгоритм может пропускать сегменты, которые уже присутствуют на облачном сервере. Это **не гарантированная принудительная перезапись** существующего архива.
- Ответ локального API **HTTP 200 — НЕ подтверждение успешной выгрузки в облако**. Необходимо проверить журнал LinkVideo.Server, состояние его синхронизации и реальный облачный архив.
- Первая интеграционная проверка должна проводиться на личном тестовом компьютере и одной тестовой камере. Операция обращается к настоящему серверу; не запускайте на продуктивном клиентском ПК до проверки.
- Прямых POST отправок `.dat` или изменения индексов Nimble приложением нет. Исходные файлы читаются, но не изменяются.

## MP4 и локальный архив

Поиск `Videos`, чтение индекса `nimble-dvr-segments.db`, вывод реальных интервалов/пробелов, выбор участка и **«Экспорт MP4»** остаются из v0.6. Экспорт выполняется через FFmpeg без изменения оригинальных `.dat`. Выходные MP4 сохраняются в `Видео\LinkVideoExports`.

## Nimble

Настраиваемый интервал мониторинга, задержка при пропаже процесса и новых записей, контроль службы Windows, ручной/автоматический перезапуск, ограничение частоты перезапуска. **Автоперезапуск по умолчанию выключен.** Требуется подтверждение работы на реальной Windows перед его включением.

## Диагностика первой попытки

1. Выбрать короткий уже существующий участок (примерно 1–2 мин) на единственной тестовой камере.
2. Нажать «Выгрузить в облако». Ввести локальный пароль LinkVideo.Server, подтвердить.
3. Записать HTTP-код и длительность. Не передавать пароль или токен.
4. Сопоставить время с журналом LinkVideo.Server (`C:\Program Files (x86)\LinkVideo.Server\logs`) и с облачной шкалой. Если облако не изменилось, это не означает, что кнопка не сработала: штатная синхронизация может исключить уже загруженные участки или вернуть ошибку только в фоновом журнале.

## Сборка и тесты

Go 1.23+. `go test ./...`, `go vet ./...`. Windows x64: `GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -ldflags="-H windowsgui -s -w" -o LinkVideo.ServerTools.exe .`

Разработка пока опирается на Win32 интерфейс. Полное оформление уровня LinkVideo.Helper будет отдельной задачей; приоритет в этой версии — проверка настоящего механизма отправки архива.
